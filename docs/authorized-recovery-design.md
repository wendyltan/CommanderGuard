# 本次授权恢复设计

用户已批准三阶段实施并要求持续推进至安装后可目测。目标是让用户在 Guard 内完成“查看中断影响、授权本次重启、查看分层证据”，同时保留无人值守自动恢复的严格保护。沿用原生 AppKit 与现有单文件结构，不引入依赖。

1. **识别与解释**：兼容新版无在线设备响应，要求明确错误类型、合法响应和目标设备匹配。保留旧版识别，未知、认证失败、其他设备不提升为明确断链。区分调用空闲与后台服务仍在，展示真正的阻止原因。
2. **本次授权**：故障页提供原生确认入口，读取并验证固定受管理服务身份、进程实例及影响范围，覆盖子进程及同进程组。展示脱敏影响、调用状态与云端未知。用户可以接受中断，但不能覆盖目标身份、读取失败、并发锁和审计保存失败。授权只在内存有效，绑定实例及影响指纹，60 秒过期，执行前重新检查。永久自动开关和云端探测开关不被修改。
3. **执行与证据**：复用固定服务重启，先保存脱敏记录，重复点击与自动恢复互斥。分开记录旧进程退出/新进程存在、ping、固定只读工具、业务未恢复/未知。联网验证由本次明确选项授权，仍共享持久间隔；关闭自动探测不撤销明确授予的本次验证。自动路径不新增周期工具探测。外部进程变化记为外部恢复。重开 Guard 不重放重启。

## 验收

离线：新版/旧版响应、错设备、错错误码、未知格式；授权取消、过期、实例或影响变化、重复执行、保存失败；探测间隔、开关不变、重开不重放；自动保护不退化。完整构建与自检、浅深色/常规最小尺寸的界面断言和截图。正式安装后哈希、偏好及持续状态核对，显示正式面板。真实破坏性演练不自动执行，人工验收待用户。

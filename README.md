# CommanderGuard

CommanderGuard 是 macOS 菜单栏里的 Desktop Commander 状态工具。它显示本机收到的命令、文件操作和单次调用耗时，并把消息通道、本机工具执行、ChatGPT 回答与网络路径分层判断。设备列表显示“在线”不等于消息一定能到达这台 Mac；`ping` 只验证消息通道，本机工具执行由独立证据验证。

下一步功能、优先级、验收条件和实施进度见 [项目待办](TODO.md)。待办中尚未完成的功能不属于当前能力。

## 安装与更新

先安装并登录 [Remote Desktop Commander](https://github.com/desktop-commander/remote-desktop-commander)，确认它在本机运行。然后在本项目目录执行：

```bash
./build.sh
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --self-test
./install.sh
```

安装脚本会构建并签名 Guard，把它放到 `~/Applications/CommanderGuard.app`，创建桌面入口和登录自启项，并重新启动 **CommanderGuard**。脚本目前使用固定项目路径 `/Volumes/ExtSSD/Projects/CommanderGuard`。它不会重启、重新登录或修改已经运行的 Desktop Commander 服务。以后若启用自动恢复，Guard 可能在确认通道失效且满足安全条件时重启该服务；见下文。

点击状态栏图标，或再次打开桌面入口，进入同一个主面板。顶部用四个紧凑状态卡分别显示“消息通道／工具执行／ChatGPT 回答／网络路径”；“自动恢复命令连接”“保持电脑唤醒”和“检查链路”始终可见。两个开关互不影响。面板下方分为：

- **概览**：先显示当前需要处理的问题、观察时间和下一步建议，再显示本机活动、ChatGPT 更新连接与最近事件。
- **操作记录**：本机命令、状态、时间与耗时，以及独立列出的 ChatGPT App 事件。概览与诊断中同一秒内相邻的同类事件合并显示次数，原始记录仍保留在事件列表和脱敏时间线中。
- **连接诊断**：Commander 连接、自动恢复、ChatGPT 回答、日志覆盖和连接事件，按主题分组。

应用图标采用盾牌与连接环；菜单栏使用同一含义的单色盾牌连接标识，继续实时显示连接标记、进行中的耗时与当前调用摘要；右键菜单仅保留打开面板与退出。面板支持调整大小、系统浅色与深色外观。“未观察到新调用”只描述当前日志中没有新调用；日志有缺口时仍会明确显示无法确认空闲。自动恢复首次安装且没有既有设置文件时默认开启；关闭后 Guard 仍会监测连接，但不会自动重启服务。

## 如何判断通道状态

Guard 启动 90 秒后开始定期发送无副作用的 MCP `ping`。收到针对本机设备、请求编号匹配的 `pong`，才确认消息通道可回应。状态栏的 `●` 表示消息通道近期能回应，`!` 表示服务未运行或通道明确报错，`?` 表示尚未确认、结果过期或网络等原因导致无法判断。该 `ping` 在 Commander 设备端直接返回，不经过本机实际工具执行。

本机工具执行另有 120 秒有效期。Guard 优先复用最近一次明确成功的真实工具调用；证据过期且本机确认空闲、日志完整、消息通道可回应时，才发送固定的只读 `list_sessions` 探针。探针响应必须匹配请求编号和当前设备归属；会话列表正文会被丢弃，只保留“已验证／失败／未知”、检查时间和必要错误类别。工具检查失败不会自行增加 Commander 自动重启条件。

当服务**连续三次明确返回“设备没有活动连接”**时，Guard 才会考虑自动恢复。普通超时、网络故障、登录失效以及无法识别的响应只会显示“状态未知”，不会触发重启。

在重启前，Guard 还会确认云端没有待执行或执行中的调用、本机日志没有未结束或状态不明的调用，并核对 Commander 进程树中没有额外子进程。检查失败、日志有缺口、自动恢复被关闭或处于冷却期时，都会暂缓重启。每次尝试前会保存五分钟冷却记录，防止 Guard 自己重启后反复尝试。重启后，只有服务进程号变化且新 `ping` 成功，才报告恢复成功。

这些检查旨在避免打断可观察到的工作，但无法保证识别所有独立运行的后台任务。通道恢复也不会重新执行命令、重试图片生成或继续发送聊天消息。

## 操作记录与状态

“操作记录”显示最近最多 100 次本机工具调用，包括经脱敏的命令与参数、观察时间和耗时。重建的历史记录会明确显示时间、耗时未知。提供命令、工具与路径搜索，以及“全部／进行中／异常与未确认”筛选。选择记录可查看完整脱敏内容、时间和耗时，刷新保留选择。顶部四层状态卡把状态作为主信息、检查时间作为次信息；较早的 ChatGPT 回答异常会明确标为历史异常，不与当前连接状态混为一项。“连接诊断”按主题显示消息通道、实际工具执行、被暂缓的检查原因、恢复开关与冷却情况，以及服务和日志状态。

CommanderGuard 只在上游远程调用 metadata 明确提供稳定会话字段时关联命令归属。目前识别 OpenAI 官方的 `_meta["openai/session"]`，并兼容 Remote Desktop Commander issue #12 建议的 `origin_context_id`；原始值进入 Guard 后立即做 SHA-256，仅保存和展示短匿名指纹，不保存原值。`origin_instance`、调用时间、当前前台聊天和终端进程均不作为会话归属依据。当前 Remote Desktop Commander 0.2.51 的云端调用 metadata 尚未透传这两个稳定字段，因此真实记录仍会显示“归属未确认”。较大的命令行即使超过普通日志前缀上限，Guard 也会用有界尾部缓冲单独读取末尾 metadata，不保留大段参数正文。详细复核见 [ChatGPT 与 Commander 会话归属复核](CHAT-COMMANDER-ATTRIBUTION-REVIEW.md)。

ChatGPT App 事件只有在原记录的会话编号与已核对的本机会话名称表匹配时，才显示名称及稳定颜色；公共连接事件和未知来源保持灰色。

Guard 还会只读 Desktop Commander 的 `~/.claude-server-commander/tool-history.jsonl` 作为独立的结构化证据源。当前安装版本的契约是：记录包含时间、工具名、参数、返回结果和毫秒耗时，约每秒批量刷盘；内存最多保留 1000 条，单条保存的输出最多 4 KiB，文件超过 5 MiB 时裁剪到约 4 MiB，启动时超过 2000 条会改写为最近 1000 条。Guard 只保留工具名、实际时间、耗时与“已返回／返回错误／未知”类别，不读取到 UI 或状态文件中的参数和结果正文。由于该格式没有可靠调用编号，Guard 不按时间把它和 stdout 记录或 ChatGPT 会话强行合并，也不把它单独用作“当前空闲”的证明。

“检查链路”先发送无副作用的 MCP `ping`；通道成功后，再复用近期真实工具成功记录或在确认空闲时执行只读 `list_sessions` 工具检查。手动工具检查同样遵守占用、日志覆盖和恢复中保护；有业务调用时只报告暂缓，不插入探针。手动检查不会启动自动恢复，也不会把手动失败计入自动恢复的连续失败次数。一次 `start_process` 返回仅表示本机启动调用结束；其后台进程可能仍在运行。本机调用返回也不能证明云端已收到结果或整轮聊天任务已完成。

Guard 从当前服务时期的完整保留日志分批重建调用状态，积压时显示剩余字节并暂缓自动重启。短暂读取失败只在同一日志文件、同一位置连续续读成功后恢复；真正丢失记录、轮换或截断时会记录原因与时间，继续允许只读 ping，但阻止自动重启。历史错误日志缺少与调用对应的编号和服务时期标记，因此启动 Guard 前已失败的调用可能保持“状态未确认”，不会仅凭安静一段时间清除。Guard 自身成功重启服务，且确认旧进程退出、新进程和 ping 可用后，才从新服务时期重新构建记录。

## ChatGPT 端监控

### 联合诊断与下一步

概览和连接诊断共用一份诊断结果。诊断检查最近 15 分钟的连接事件；ChatGPT 与 Commander 连接错误的时间相差不超过 10 秒时，提示两端近期同时异常，并建议检查共同的联网路径。ChatGPT 使用原始日志时间，Commander 使用本机观察时间；这种时间接近只提示可能有关联，不能确认根因、代理故障或同一会话。

已安装 TunnelSentinel 时，Guard 只读它的选定状态：检查时间、网页探测、代理可用性、隧道状态、手动暂停及失败计数。文件缺失、格式无效或超过 120 秒时显示未知。不读取它的节点、配置、探测正文或原始日志，也不启动、重启或修改它。网页探测正常无法证明 ChatGPT 持续连接稳定。

同一秒附近的多条更新连接关闭记录合并展示，避免把并发连接的记录误当作多次完整故障。已经观察到重新连接时仍保留中断经过；较早的回答恢复异常单独保留，不用 ping、网页探测或更新连接重建来清除。当前服务或连接故障优先于旧回答异常。没有可靠的异常开始时间时显示暂无，不把最近检查时间当作故障开始时间。

“下一步”是根据当前证据给出的处理建议，本批不会因此执行新的恢复动作。屏幕提示补报、恢复后的分层复查、通知等后续功能仍以 [项目待办](TODO.md) 为准。

主面板顶部显示独立的 ChatGPT 回答状态。“连接诊断”分别显示最近回答异常、原始事件时间和公共更新连接状态。监控当前本机 App 的固定结构化事件：回答恢复尝试、恢复流不可用、恢复完成、恢复检查失败、对话状态刷新失败，以及更新连接关闭、失败、重连、重连耗尽和建立。启动时分批读取 App 日志最近 2 MiB，并从脱敏时间线恢复最近异常。“恢复完成”仅说明对应日志记录的恢复路径成功，不表示其他异常或所有会话已恢复。连接重新建立或界面变为空闲，不会把原回答标为恢复成功；没有异常记录也不等于连接正常。

本机当前 App 的 `Connection interrupted` 提示表示响应中断后转入轮询等待完整回答；`Message delivery timed out` 表示这段轮询等待超时，不能据此判断用户消息没有发出。当前日志没有专门的最终轮询超时事件，Guard 能识别相关恢复异常，却不能保证直接识别每次屏幕提示。手机、其他电脑或浏览器上的提示也可能不进入本机日志。

Guard 不提取、保存或展示聊天正文，不自动发消息或重试任务，也不重启 ChatGPT 或切换网络。看到异常后，先回到原会话核对完整结果与本机操作记录，再决定是否手动继续。防休眠可减少本机睡眠导致的断连，但无法恢复服务端不可用的回答流，或保证云端任务不中断。

对当前 ChatGPT App 26.930.31730 的只读代码复核确认，App 已有响应流心跳接收、无数据超时、续传重试和轮询兜底。Guard 可以补充观察这些事件；额外访问网站或新建连接无法保活 App 原有回答流。匿名联网检测只能判断 DNS／HTTPS 可达性，不能确认登录会话或回答已完成。当前没有验证到适合第三方 Guard 控制原回答流的受支持接口；详见 [ChatGPT 探测与保活复核](CHAT-LIVENESS-REVIEW.md)。

关闭“保持电脑唤醒”会释放 Guard 对本机防空闲睡眠的设置，日志观察继续运行。它不能恢复 ChatGPT 的回答流，也不能保证远程任务持续运行。

本机状态保存在 `~/Library/Application Support/CommanderGuard/`：

- `status.json`：当前服务、通道和调用状态。
- `timeline.jsonl`：脱敏事件时间线，最多 1 MiB，保留一个轮替副本。
- `channel-recovery.json`：自动恢复开关及最近尝试时间，不含登录凭据。

Guard 读取已有的本机登录信息来查询设备登记与待执行调用，并发送固定的 `ping`；在工具执行证据过期且满足空闲保护时，可发送固定的只读 `list_sessions` 探针。它不写入或刷新登录凭据。探针正文、令牌、原始会话标识和命令结果不会写入状态或时间线；命令预览会隐藏常见凭据及内联脚本，自定义的秘密格式仍应避免放入命令行。

## 单独检查与卸载

离线自检不会启动 Guard 或操作 Commander 服务：

```bash
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --self-test
```

只查看固定示例界面时，可运行离线预览；使用固定示例数据，开关和检查按钮禁用，不启动监控或恢复，也不写入状态：

```bash
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --preview-ui
```

检查面板三页在常规与最小尺寸下的布局，以及操作记录选择后刷新是否稳定：

```bash
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --preview-ui --verify-ui
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --preview-ui --preview-dark --verify-ui
```

界面采用原生 AppKit，布局参考 [Little Snitch 的概览、列表与详细信息分层](https://help.obdev.at/littlesnitch6/lsm-overview)，以及 [Stats](https://github.com/exelban/stats) 的菜单栏监测用途；不引入额外 UI 依赖。

需要分别验证当前消息通道与真实本机工具执行时，可手动运行一次只读探测；它们都不会执行自动恢复：

```bash
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --probe-channel
./build/CommanderGuard.app/Contents/MacOS/CommanderGuard --probe-tool
```

卸载 Guard：

```bash
./uninstall.sh
```

卸载脚本会移除 Guard 应用、桌面入口和登录启动项，保留项目源码及状态文件。
